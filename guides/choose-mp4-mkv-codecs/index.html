MP4, MKV, H.264, HEVC, AV1 and remux: choosing output settings

A container is the box and a codec is the compression. MP4 is usually the safest choice for playback, while MKV gives you more room for advanced tracks and archival codecs. In Kacher you set one batch profile and apply it to a list of files.

Kacher checks which encoders are available in your FFmpeg build. Some GPU encoders may not be present on your system; then the app uses CPU or reports that a selected GPU mode is unavailable.

  1. Start with the playback destination

    For broad playback and editing in common players, choose MP4. For ProRes or DNxHR editing, MOV is the natural container. For FFV1 archive, use MKV.

  2. Pick a codec by compatibility, size and purpose

    H.264 plays almost everywhere. HEVC/H.265 often uses less space but needs a newer player. AV1 can compress further, but it is slower and less universally supported. ProRes, DNxHR and FFV1 are editing and archive choices, not everyday playback formats.

  3. Use remux when you do not need a new encode

    Remux copies the existing streams without re-encoding. It is fast and lossless for the streams themselves, but it cannot resize the picture, change the codec or fix the audio.

  4. Set container, codec, resolution and fps together

    Your plan's maximum height remains a ceiling even when you choose a taller aspect ratio. Check the output resolution, fps and audio options before starting a large folder.

  5. Check the GPU path before a long job

    Use Auto or Check GPU to see the available NVENC, AMF, QSV or MediaFoundation encoders. If a chosen GPU encoder fails, Kacher can fall back to CPU for the next attempt; in custom mode it uses the selected codec first and then a compatible fallback.

  6. Validate one file before a full folder

    Run a short test on one file, then open the result and verify the codec and duration. Kacher also keeps failure logs under its logs folder when an item fails.

What to check before you call it done

  • The container supports the chosen codec.
  • HDR sources keep their color tags; this does not create HDR from an SDR source.
  • Remux has not been used where the picture or codec must change.
  • The output height respects the plan limit.

Questions before you install

Why does Kacher ask for MKV with FFV1?

FFV1 is treated as an archival choice in Kacher and needs MKV. A non-MKV choice will not silently fall back to a different codec.

What if my GPU encoder is missing?

Use Check GPU and Auto. If the GPU encoder is unavailable, Kacher can use CPU instead, which is slower but works on ordinary hardware.

When is remux enough?

Remux is enough only when the existing streams already fit the container and playback target. It cannot resize, change the codec or repair audio.
