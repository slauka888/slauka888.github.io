MP4、MKV、H.264、HEVC、AV1 和 remux：如何选择输出设置

容器是盒子，编码是压缩。MP4 通常最适合播放，MKV 则给高级音轨和归档编码留了更多空间。在 Kacher 里设置一个批量配置，并应用到文件列表。

Kacher 会检查你的 FFmpeg 构建里有哪些编码器可用。有些 GPU 编码器可能不在这台机器上；这时应用会用 CPU，或提示所选 GPU 模式不可用。

  1. 先看最终播放位置

    要在常见播放器里广泛播放和剪辑，选 MP4。ProRes 或 DNxHR 剪辑用 MOV。FFV1 归档用 MKV。

  2. 按兼容、大小和用途选编码

    H.264 几乎到处都能播。HEVC/H.265 常更省空间，但需要较新的播放器。AV1 压缩更强，但更慢、兼容性更差。ProRes、DNxHR、FFV1 是剪辑和归档选择，不是日常播放格式。

  3. 不需要重新编码时才用 remux

    Remux 直接复制已有流，不重新编码。它对流本身快速无损，但不能改变尺寸、编码或修复音频。

  4. 一起设置容器、编码、分辨率和帧率

    即使改了纵横比，套餐的最大高度仍然是上限。大批量处理前检查输出分辨率、帧率和音频选项。

  5. 长任务前检查 GPU 路径

    用 Auto 或检查 GPU 看看 NVENC、AMF、QSV、MediaFoundation 哪些可用。如果 GPU 编码器失败，Kacher 会在下一次尝试时回退到 CPU；自定义模式会先用所选编码，再用兼容的备用。

  6. 先拿一个文件验证，再跑整个文件夹

    先拿一个文件做短测试，打开结果检查编码和时长。失败时 Kacher 还会在日志文件夹里保存失败日志。

完成前检查清单

  • 容器支持所选编码。
  • HDR 来源会保留色彩标签；这不会把 SDR 变成 HDR。
  • 需要改画面或编码时没有用 remux。
  • 输出高度符合套餐限制。

安装前常见问题

为什么 FFV1 要用 MKV？

Kacher 把 FFV1 当归档选择，需要 MKV。换成别的容器不会静默回退到另一种编码。

GPU 编码器不存在怎么办？

用检查 GPU 和 Auto。如果 GPU 编码器不可用，Kacher 可以用 CPU：更慢，但在普通硬件上能跑。

什么时候 remux 就够了？

只有当已有流已经符合容器和播放目标时才够。它不能改尺寸、编码，也不能修音频。
